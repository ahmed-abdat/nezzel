# Security policy

## Report privately

Email [contact@hululsoft.mr](mailto:contact@hululsoft.mr) to report a suspected vulnerability privately. Keep exploit details out of the first message; we can arrange a private follow-up. Do not open a public issue containing vulnerability details.

You can also use [GitHub private vulnerability reporting](https://github.com/ahmed-abdat/nezzel/security/advisories/new) (**Security → Advisories → Report a vulnerability**).

Include the affected app/build and engine versions, Android version, impact, and minimal reproduction steps using synthetic or rights-cleared public inputs. Never send signing keys, passwords, cookies, access tokens, private URLs, full clipboard contents, or unredacted device logs. Describe sensitive input shapes instead.

Keep investigation limited to your own device/data or an isolated test setup. Maintainers will coordinate reproduction, a fix and disclosure through the private reporting channel. There is no promised response deadline or bounty program.

## Supported versions

During early development, fixes target the [latest release](https://github.com/ahmed-abdat/nezzel/releases/latest) and the current main branch; older releases have no backport commitment. State your version when reporting. Open distribution and dependency-provenance limitations are tracked in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md); this policy is not a security certification.
